### 2.3 Summary - classes
`GET /reports/summary` (:407, via :380) and `/summary/download` (:425). Inputs: gender, `from` (default 3 months back, first of month), `to` (default current month), level. Response per class `{classId, level, class, teacher, expected, conducted, notFilled, notConducted, avgStudents, avgDuration, percentNotFilled, percentConduction, percentAttendance, subjects:{arabic|aqaed|ahkam|akhlaq|other:{count,percent}}\|null}`; every figure rounded to int. ### 2.4 Students - classes (+ recitation from content-owned logic)
`GET /reports/students` (:529, via :508), `/students/download` (:694). Inputs: gender, `from`,`to` dates (default last 30 days to today), <=366 days. Returns every student of every reachable class: `{gender, from, to, levels[], classes[{class,level}], students[{token,name,level,class,sessions,attendance%,totalMcqs,mcqAttempted%,mcqPerformance%,recitation,recitationAvg,tsrScore%}]}`; percentages int, sorted by `performance desc`. Also `ClassesModel::getLevels()`. Cost M (one year ~50k attendance rows) plus global leaderboard scan over the same window.

### 2.5 TSR at a glance - classes
`GET /reports/tsr` (:612, via :590), `/tsr/download` (:742). Inputs: gender, dates (default last 14 days), <=366 days. Response `{gender,from,to, conduction:{levels[{id,code,conducted,total,percent}], classes[{level,class,teacher,lastConducted}]}, mcq:{...same}, attendance:{levels[{id,code,percent}], classes[{level,class,teacher,percent}]}, recitation:{levels[{id,code,total}], classes[{level,class,teacher,total}]}}`. 8 queries (mis.php:1078-1195, 1594-1780). ### 2.6 Pending - classes (+ nudge in notifications)

Writes: `notifications`, `user_notifications`, `log_event('cc_nudge.sent')`. Fixed text template (`pendingnudge.php:message`).

### 2.11 Quran leaderboard - content (csv domain)
`GET /reports/quran-leaderboard` (:1629, via :1588): top 100. `/download` (:1649): all ranked. Guard `quran-leaderboard:read` (+ genderLock on that action). Inputs gender; `from`,`to` dates (default 1 year back .. today, <= 5*366 days, 422 `The range can cover at most five years`); `level` (name; 422 `Unknown level`); `minimum` (int >= 0, else 1; applied via `HAVING total_recitation >= :minimum`). Response `{gender,from,to,levels[],total,students[{rank,name,token,class,recitation}]}`. Download columns Rank, Name, Token, Class, Recitation. A member in two active classes appears twice with the same rank. Does **not** apply the demo-class exclusion and does not check `class_students.removed_at` (only `cs.status='A'`), unlike the MIS reports.

## 4. MIS report (`models/mis.php`), full detail

`MisModel` is one 3464-line class. Reports reached from `/reports/*` use lines 1-1600 and 1783-2335; **lines 2339-3464 (dashboard KPIs, risk, locations, curriculum coverage, lifecycle, `searchPeople`, `getPersonProfile`) are called only by web `dashboard.php`**, not by any API route (grep of callers).

Scope plumbing: `reach()` (:18) caches `managedReach(user,'reports:read')` + `assigned` flag; `reachFilter()` (:41) described in section 1; `getClassFilter()` (:1197) = reachFilter + optional `c.class_level_id` + dashboard location SQL (empty for API) + demo exclusion; `reportClasses()` (:685) = `ClassesModel::getAll(gender)` (which itself limits by `assignedOnlyIds(user,'classes:read')`) filtered by `PermissionsModel::reaches` and demo id. **Two scope mechanisms coexist** (SQL fragment vs PHP filter over `getAll`), plus `classes:read` assigned limit inside `getAll`.

Date helpers: `getDates(MM-YYYY, MM-YYYY)` (:136) = first day of start month moved back to Sunday, last day of end month capped at `time()` then moved forward to Saturday (default start `01-2022`); `getDatesNew` same for `YYYY-MM`. `get_week_range(y,w)` = min/max `dt` of `calendar_table` for that (y,w); `lastCompletedWeek()` = (y,w) of `current_date - 7 days`; `weekNeighbours` steps +/-1 day from the week bounds (week split by New Year).

Queries, in order:
1. `calendar_table` point reads (`weekOnDate`, `get_week_range`): `select y,w from calendar_table where dt = X`; `select min(dt),max(dt) from calendar_table where y=:y and w=:w`.
2. **`summary_legacy`** (:345): subquery `cl` = weeks `(y,w,min(dt),max(dt))` of `calendar_table` between start/end; `inner join classes c on (c.started_on is null or c.started_on <= cl.max_dt)` (cross product classes x weeks); `inner join class_levels l`; `inner join users t on c.teacher = t.token`; `left join (class_students count where removed_at is null group by class_id) st`; `left join class_sessions s on s.class_id=c.id and cl.min_dt <= s.conducted_on <= cl.max_dt`; where `c.status='A'` + demo + reachFilter; outer filter `From >= Started On` (`started_on` else `created_at`); order gender, level sort, numeric part of code (`substr(code,3)`), week start. Computed in SQL: `Conducted` Yes/No/Not Filled (null/1/0), `Extra` = newline count in `extra_students`. If a class held two sessions in a week the row **duplicates** (left join), later counted twice in `conductionSummary`.
3. `conductionSummary` (:448): per class: Expected = week rows; Conducted = Yes; Not Filled; Not Conducted; Attendance sum over Yes rows; `% Conduction` = conducted/(expected-notFilled); `% Attendance` = (attendance/conducted)/(registered+extra); `lastConducted` (unused in the API response).
4. `weeklyReport`/`details` (:194): `class_sessions s ⨝ classes c ⨝ class_levels l ⨝ users t`, `s.conducted_on between window`, `c.status='A'`, demo, reachFilter, optional level ids, order level sort. Parameter binding is used for the dates only; level ids are int-cast.
5. **`summary()`** (:917): described in section 3. Subqueries: `e` (expected slots) = classes ⨝ `class_schedules` (deleted_at null) ⨝ weeks of `calendar_table` where `dt >= greatest('2021-11-01', from)` and `dt <= least(now(), to)`, week fully inside `[greatest(ifnull(started_on,'2021-11-01'), from), least(now(), ifnull(shutdown_on,now()), ifnull(completed_on,now()), to)]`, `dayofweek(min_dt) <= cs.day and dayofweek(max_dt) >= cs.day`; `a` = sessions grouped by class (submitted, conducted, duration sums where conducted and duration>0, 5 subject counts via `*_conducted IN ('1','Y')`); `s` = attendance rows (count, sum present) for conducted sessions in the window. Note the `s` join is `on e.id = s.class_id`. Dates are concatenated into SQL (validated earlier by the formats); `class_schedules.timezone` is not used. `students` (Avg Students) = present / conducted. `% Conduction` = conducted / expected when submitted>0.
6. `summaryReport` (:1060): rounds 19 figures to int. Default start = 3 months back (`first day of this`).
7. `getConductionReport`, `getSummaryConduction`, `getMCQReport`, `getSummaryMCQs`, `getAttendanceReport`, `attendanceSummary`, `recitationSummary`, `getQuranRecitationSummary` (:1078-1780): all `getClassFilter` + `getDateCondition`; per-level pivots `count(case when c.gender=1 ...)`; attendance fraction `act/exp` per class where exp counts attendance rows; recitation sums `class_attendance.recitation`.
8. `studentPerformance` (:1213): six derived tables each re-joined to `classes` with the same filter: `att` (class_id, token: count rows, sum present), `quiz_conduction` (class_id: count quizzes), `quiz_questions` (class_id: count questions), `quiz_responses` (class_id, token: distinct quizzes answered, sum is_correct); score formula in section 3. `withRecitation` (:1369) joins by token in PHP.
9. `pendingReport` / `pendingByTeacher` (:1453-1512); `mcqSummaryReport` (:1531) and `mcqAdherenceReport` (:1567) loop `reportClassesWhere`.
10. `subjectConductionSummary` (:1788, web only?) and `subjectConductionWeekly` (:1858, API): see 2.7; `subjectTaughtSql` = `cs.<subject>_conducted IN ('1','Y')` (the topic text is deliberately not used; #607).
11. `activeTeachers` (:2024), `getClassesByLevel` (:2082, web), `subjectConductionClasses` (:2119), `getClassSessionsReport` / `History` / `Export` (:2140-2335): history re-checks reach via a gender read on `classes` then `getClassFilter` + `select id ... c.status='A'`.
12. `onlyReportable`, `weeklyCell`, `weeklyMonths` (:695-770): pure PHP.

Quirks the designer should know: (a) `weekAttendance` and `studentPerformance` etc. compare `spot_quizzes.published_at` (datetime) to a bare `YYYY-MM-DD` upper bound (excludes the last day after 00:00); (b) strict `$r['Week'] === $week` int compare in `conductionReport` relies on PDO returning ints; (c) `summary_legacy` returns `[start,end,rows]` but a start>end early return has string keys (unreachable from the API); (d) one class with two sessions in a week duplicates its week row; (e) `Registered` counts today's roster even for past weeks.

## 7. Open items and discrepancies found

2. `GET /reports/summary` does not enforce the 12-month cap (only conduction/weekly/pending/subject-conduction do), so a request can scan all attendance.

8. Members are keyed by token in classes/assessment but by user id in membership; token 0 is shared by guests; teacher/student name and gender lookups need token -> user id (identity) first.
