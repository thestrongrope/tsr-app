## The blocker (decision needed from the owner)
Routes 2, 8 and 12 insert a quiz, and a quiz needs the random unique `code` PHP's trigger `spot_quizzes_before_insert` sets (`tools/synthetic-data/schema.sql` in the PHP source: 8 characters, `LPAD(CONV(FLOOR(RAND()*POW(36,8)),10,36),8,0)` = base 36 digits and UPPER-CASE letters, regenerated while a quiz with that code exists; any supplied code is overwritten).
The brief said to retry on a unique violation and to STOP if the unique index is missing. It is missing: the new schema has no index on `spot_quizzes.code` (migration `Initial` has only `idx_sq_class_published` on that table), and PHP had none either (its trigger checks `NOT EXISTS`, racy under concurrency, and by-code lookups scan).
Adding a unique index is a schema change on a table that may hold duplicate or empty codes in the real data (PHP never enforced it), so it is not a small views-only change. Proposal: (1) count duplicate and NULL/empty `code` values on the parity and test data (and, with approval, on a copy of production), (2) one migration: fix or null the duplicates, then `create unique index ... on assessment.spot_quizzes (code)` (citext, so case-insensitive like the by-code route), (3) port the generator once in `domain/` (8 chars of `0-9A-Z` from `RandomNumberGenerator`, retry up to a small bound on `PostgresErrorCodes.UniqueViolation` for that index), then build 2, 8 and 12 on it.
PHP facts already read for that batch (`mcq_admin.php`, `models/mcq.php`):

- Route 8 (:658, model :1240): class active, `mcqs:manage` on the TARGET class only; 404 "Standard MCQ not found" from `standardMcqExists` (a row of `standard_mcqs` by id, `deleted_at` not looked at); then ONE raw multi-statement `exec` with no transaction: the quiz is inserted with `code ""` (the trigger sets it), `mcq_code` = the standard code, name `subject - lesson - name`, the class's id, the standard's topic, `restrict_to_class` 1, `created_by` the caller; its questions are inserted under `MAX(id)` of `spot_quizzes` (a race) with `option1` = the standard `answer`, `option2` = its `option1`, `option3` = its `option2`, `option4` = its `option3`, `option5` NULL, `answer` 1. There is NO duplicate rule: a second copy of the same standard MCQ into the same class is accepted (PHP's own list then multiplies the question count, see route 7). No level or language check, no check that the standard MCQ has questions. Plan: one transaction with database-generated ids.

- Events to write then: `assessment.quiz_created` `{quizId, classId, token, source: new|standard|copy}`.

### 5. PUT /mcq/manage/{quiz_id}: `features/manage-update/`, `domain/QuizEdit.cs` (+ tests), `manage-update.hurl`, `manage-update-new-api.hurl`
PHP :193, McqModel update :682, addQuestions :728. One transaction: update the quiz (`modified_by`, `modified_at`, `restrict_to_class` only when sent), DELETE all its questions, INSERT the new ones (`answer` 1, `is_arabic` and `option_display_order` NULL), one outbox row `assessment.quiz_updated {quizId, classId, token}`. The quiz row is updated first, which takes its row lock: eight simultaneous edits leave one set of questions (db test).
Quirks copied (found by running PHP): a row that is not an object or has neither question nor answer is skipped; only one of them is 422 "Question N needs both a question and an answer" (N = key + 1); a missing option is `''`; the text `null` is a database null (also as the answer: the stored option1 is then NULL); a question whose text is `0` is counted in `questionCount` but NOT stored (PHP's falsy "0"); `restrictToClass` 0 for anything PHP reads as 0 (`"abc"`, false), left alone when absent; `questions` missing or not an array DELETES every question; a name that is a list is the text "Array".
Deviations (422): a text over its column (name or topic 300, question or option 1000 characters), a NUL byte, more than 500 rows (PHP: 500 "Failed to save quiz" on a strict database, a stored NUL, no cap). A database failure is the host's generic 500, not PHP's "Failed to save quiz" text. PHP prints warnings into the body for a wrong JSON type; not copied.
**FLAGGED, COPIED FROM PHP: what an edit does to existing answers.** There is no check for a published quiz or for answers. Deleting the questions leaves every stored answer in `spot_quiz_responses` (no foreign key, as in PHP) pointing at deleted question ids. A student's correct count stays, but their score is measured against the NEW question count (answers 2 of 2 become "2 of 3, 66.67%" in my-score and the class lists), their old answers read back with no question text, and a student whose score is above zero stays locked out of the new questions. The option order is reset too (`option_display_order` null), and `is_arabic` null. Pinned by `manage-update.hurl` (PHP and new API) and by `AssessmentA2Tests.FLAGGED_an_edit_of_an_answered_quiz...`. Refusing edits of published or answered quizzes is the owner's decision; only the permission guards it today.
