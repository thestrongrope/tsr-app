### Quirks copied
- `/me/children`: `gender` is PHP's `(int)` cast ("Male" is 0, here and only here; the subscriber card uses `genderOf`: Male is 1). Classes are not distinct. A token shared by two members repeats the child. At most 200 links, 2000 class rows (deviation, PHP has no cap).
- Create, list and cancel share `api_require_parent_link_create`: a token of 0 or less is 404 `Student not found` BEFORE any permission; a student acting for themselves (`parents:manage`) is not checked for existence; staff reach is `staffMayAddFor` (reach all, or the child's gender, or `can` on one of the child's active classes, at most 200 classes); a staff caller without `parents:add` is 403, with it and out of reach 404. Create: a guest, unknown or shared child token is 404 (the 422 is only the cap). `link` and `url` are equal. List: `ORDER BY id DESC LIMIT 5`, a NULL expiry is `""`, only the caller's own invites. Cancel: no expiry check; creator or `parents:manage` for the child's gender (an `(int)` cast of the stored text); everything else 404 `Invite not found`.
- Candidate: order is permission (403), the limit (429, counted for every call that passes the permission), staff reach (404 `Member not found`), then the member (shared token: 422 with `code: ambiguous_token`, only to staff in reach). Name only, an empty name is `""`.
- Add by token: NO early `token <= 0` check (a caller with no permission is 403 even for token 0); `parent_token` and `relationship` are casts of the body; checks in PHP's order (parent, then child, then self link, then the caller as parent, then the relationship, then under the lock the 409, then the 403 text `Child previously revoked this parent; admin approval required`, which differs from the accept's text).
- Reject: guard 403 / 409 / 403 as `api_require_waiting_registrant` (a registration answers only as its member's LATEST row: id is the member's MAX id, the status is the member's MAX status, so one Rejected row ends the wait), then `registrations:reject` for the registrant's gender, then the body. The UPDATE changes EVERY row of the member (PHP too). Reason: `trim` (also strips NUL at the ends), 1 to 500 code points, non-strings are ''.
- Donors: no DISTINCT (a member in two live classes appears twice), no reach limit, every column `text?`, order by name. Deviation: 50000 rows at most.
- Subscriber card: 404 for everyone who does not reach every class (`Reach.All`), for a member in a live class, unknown, token <= 0 or text; `registeredOn` is the day of the member's LATEST registration (UTC), `requestedClass` its class code when the class exists.

## Deviations from PHP
- A NUL byte in the reject reason is 422 (PHP stores it); the only text that reaches SQL. Every other input is an integer cast or a whitelist.
- Lists capped (50000 donors, 200 links, 2000 class rows, 200 classes in a reach check).
- `TSR_PUBLIC_WEB_BASE` (configuration; unset: no base) replaces PHP's `public_web_base()` (from `REDIRECT_URI`). Not set on the test stack, so `link` starts with `/link/` there, as on the parity PHP.
- The candidate limit is per process in memory (PHP: a file). Add by token and reject take no lock beyond the child's guardian lock (PHP: the same).
- The invite is created with a transaction and the guardian advisory lock (class 3001) instead of PHP's `UPDATE users SET roleid = roleid` row lock.

## Flagged: deploy risks (outside this batch, not fixed)
- POSTs with no body get 400 through the gateway. `hosts/gateway/default.conf` has no `proxy_http_version`, so nginx talks HTTP/1.0 to the API (seen in the API log) and Kestrel rejects an HTTP/1.0 POST with no Content-Length before any handler runs. PHP's create-invite takes no body and the app calls it as `_apiClient.post(...)` with no data (`mobile/lib/features/parent/repositories/parent_repository.dart:131`). If that request carries no Content-Length (not checked: a Dart `HttpClient` normally sends `Content-Length: 0`), the new API breaks a store-live build (root rule 7). Check with the real client before the route moves; the fix is `proxy_http_version 1.1` or a Content-Length on the proxied request, which is the gateway's.
- Invite links: `TSR_PUBLIC_WEB_BASE` is wired nowhere (compose files, deployment) and the gateway already sends `/members/*/parent-links` to the new API. Production must set it to what PHP derives from `REDIRECT_URI` (`https://host[:port]`), or every invite link is relative (`/link/<code>`).
