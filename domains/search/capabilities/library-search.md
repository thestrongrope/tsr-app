# Library search (article search and lecture search)

Owner domain: `search` · Status: partial (both routes built and passing on the native image, 28 Nov 2026; analytics, the comparison with the live site and the article body are not built)

<!-- Living document: describes TODAY. Rewrite in every PR that changes behaviour. Template: docs/templates/capability.md -->

## 1. Purpose
The app's Library searches the published articles and the lectures. Released app builds call the website's two routes, so the API answers at the same paths with the same parameters and answer shape: `GET /api/v1/search` (articles) and `GET /api/v1/lectures/search` (lectures, with a meaning layer on top of the keywords). Nothing the app calls then needs the old website, its Elasticsearch or its embedding service.

## 2. Actors and scope
- **Actors:** a reader (member or guest, never signed in on these routes); the system (the `library-search-feed` worker, the embedding service).
- **In scope:** the two routes, the indexes `tsr-articles` and `tsr-lectures`, their feed, the embedding service client.
- **Out of scope:** member and class search (`GET /search`, `domains/search/CLAUDE.md`); making the lecture data and its vectors (the lecture file and its mask are content's: LEC-R8 to LEC-R10 in `domains/content/capabilities/lectures.md`); the site's `/lectures/` page, which reads the file, not this route; the admin reindex routes (the worker replaces them); the app's cut-over to this API.

## 5. Rules and permissions
Public reads (`security: []`, rule 4 of `domains/CLAUDE.md`): no caller, no `access` check. They return only published data: the article index is fed from `content.v_published_articles`, which holds published articles only. The lecture data is public (LEC-R8). The bounds are in SRCH-D16.

## 6. Interfaces
- **API:** the two routes in `spec/api.yaml`; contract tests in `spec/tests/` (section 3). The gateway sends both to the new API (`hosts/gateway/default.conf`); the catalog lists them in `RouteCatalog.NotInPhp`.
- **Worker `library-search-feed`:** one full reconcile of both indexes at start and every 10 minutes, one at a time under advisory lock 8100002 (`domains/search/CLAUDE.md`). Articles: read from `content.v_published_articles`, newest first, no body. Lectures: read from the file named by `TSR_LECTURES_FILE`, each line indexed as it is, the 19 lectures without a vector too. Both indexes are created at the first tick even when their source is empty or missing; an empty or unreadable source keeps the index and logs one warning of counts. An unchanged source is not sent again. A retry rule for the start-up race: SRCH-D20.
- **Embedding service:** `hosts/embeddings` (model `BAAI/bge-small-en-v1.5`, 384 numbers), called as `POST /embed` with a 1.5 s timeout. A vector that is not 384 finite numbers, is all zeros or is over the size limit counts as no vector.
- **Settings** (all optional; `TSR_ELASTICSEARCH_URL` and `_PASSWORD` as in `domains/search/CLAUDE.md`): `TSR_EMBEDDINGS_URL` (empty: the layer is off), `TSR_LECTURES_SEMANTIC_WEIGHT` (above 0 switches the layer on; the compose files set `0.25`), `TSR_LECTURES_FILE` (the feed's lecture file; fixed in `docker-compose.yml`, `docs/deployment.md`). Constants: keyword weight 1, embedding timeout 1.5 s, 60 requests a minute.
- **Events:** none.

## 7. Data
No tables. Indexes `tsr-articles` and `tsr-lectures` (mappings in `domain/LibraryIndexMappings.cs`, the website's), rebuilt from their sources, so losing one loses nothing. Articles and lectures are public data; no member data, no query is stored.

## 9. Known limitations, gaps and open questions
- **Not built:** search analytics (no event is written, there is no `POST /api/v1/events`; SRCH-D2); the comparison with the live site (SRCH-Q1, SRCH-Q2 have no test); the article body in the index (SRCH-D3).
- **Quirks kept from the website:** an article search with no term left (for example "of the") matches every article; article `pagination.total` is the page's count; with the layer on and no vector, a lecture page at offset 50 or more is empty while `hasMore` can be true.
- **Test gaps:** no test that a log line never holds the query text, except the embedder's; no test of the 10 minute interval or of the 260 MB.
- **Unchecked:** the `embeddings` service and both searches on production with data (`docs/status.md`).
