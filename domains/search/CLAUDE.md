# domains/search/

The read model behind `GET /search`, the domain's only operation. **Status: built; proved up to the index boundary on both sides and against a fake index (test lane edge, `docs/specs/initial-build/test-edge-notes.md`); never run against a real Elasticsearch.**
No tables. The index is Elasticsearch (index `tsr-search`, official client `Elastic.Clients.Elasticsearch` 9.5.3), settings `TSR_ELASTICSEARCH_URL`
and `TSR_ELASTICSEARCH_PASSWORD` (both optional: without a URL every kind answers as `unavailable`). The slice is `api/features/search/Search.cs`;
the rules are in `api/domain/`: `SearchPlans` (reach to a filter in the query), `SearchEngine` (query, re-check, cap), `SearchRequestRules`
(`q`, `kinds`), `ElasticSearchIndex` (the one boundary, `ISearchIndex`), `SearchFacts` (the re-check reads, `ISearchFacts`).

- Dependencies: `access` (`Permissions`; `SearchModule.Dependencies`). Other domains are read through their published views in SQL:
  `membership.v_members` (name, the caller's gender), `classes.v_classes`, `classes.v_enrolments`, `classes.v_teachers` (the teacher re-check), `classes.v_guides` (the guide re-check: dropped when the guide is gone, titled from the database; only levels 2 to 5 have a page, as PHP's slugs).
- **The feed: worker `search-feed`** (`api/workers/SearchFeedWorker.cs`, run mode `--workers`, name in `TSR_WORKERS`). No per-change queue and no event consumer (owner decision, 12 Nov 2026): it does a FULL RECONCILE once at start and every 10 minutes (what PHP's `reindex_search` does nightly). `domain/SearchFeed.cs` is the algorithm (ensure the index, list the ids present, upsert the source in batches of 500, then bulk delete the ids present and not seen); it refuses the delete phase when the source yielded no document, and an Elasticsearch failure ends the tick before any delete. Logs hold counts only. `domain/SearchDocumentSource.cs` reads the documents through the published views only (`classes.v_classes`, `v_enrolments`, `v_teachers`, `v_guides`, `membership.v_members`; no view needed a new column), 1000 rows a page. The write side is `ISearchIndexWriter` (`ElasticSearchIndex.Writer.cs`, mapping in `SearchIndexMapping.cs`, identical to PHP's); `UnconfiguredSearchIndex` makes the tick a no-op. **Advisory lock key 8100001** (session lock, `pg_try_advisory_lock` on the run's own connection; a tick that finds it held is skipped); no other code uses it. Not verified against a real Elasticsearch. Until a worker container runs it, PHP's `drain_search` and `reindex_search` still feed the index; PHP's outbox rows for search are no longer needed by this worker.
